# 画面效果：自动取景、背景虚化、人像平滑

> `crates/sidelens-frame-effects`。19 项测试，跨平台可跑。

## 为什么不引 ONNX 模型

rng-lens 的人像分割用的是 ONNX 模型。这条路线有两个现实问题：

1. **模型文件进不了仓库**（体积与许可），「可自动验证的发布产物」会退化成
   「先下载一个模型」；
2. **CI 上没有 GPU**，推理路径跑不起来，等于这块永远测不了。

这里换成不需要模型的近似：

| 效果 | rng-lens 做法 | 本模块做法 | 为什么这样够用 |
| --- | --- | --- | --- |
| 自动取景 | 人脸/主体检测网络 | 亮度梯度显著性 + 积分图找最优窗口 | 视频会议里的人是画面中细节最多的区域 |
| 背景虚化 | 语义分割逐像素 alpha | 中心椭圆 + 羽化 + 可分离盒式模糊 | 摄像头视角固定时人总在中间 |
| 人像平滑 | 皮肤分割 | 双边滤波近似（保边降噪） | 肤色平滑的需求本质是「降噪但别糊掉五官」 |

效果不如模型，但**每一条都能写成断言**，而且默认关闭、开销可测。

## 自动取景

```text
   Y 平面 ──▶ 显著性图（下采样，局部梯度）──▶ 积分图 ──▶ 枚举窗口取最大
                                                        │
                                        与上一帧按 smoothing 指数平滑
```

### 为什么用梯度而不是亮度

一盏顶灯很亮但没有细节。用亮度绝对值做显著性，窗口会追着光源跑；
用相邻像素差（L1 梯度）则追着**有纹理的区域**跑 —— 人脸上有大量边缘。

### 为什么必须平滑

不做平滑时，画面里两只手交替移动会让窗口逐帧来回跳，观感比不裁还差。
`smoothing=0.85` 是折中：再高跟不住人移动，再低仍有可见抖动。
测试 `平滑让窗口不逐帧跳动` 断言平滑结果落在旧窗口与新窗口之间；
`尺寸变化时不做平滑而是直接取新窗口` 断言用户改 scale 时能立刻生效。

### 偶数对齐

窗口的 x/y/宽/高都必须是偶数 —— NV12 的裁切约束（见
[frame-transform.md](frame-transform.md)）。`自动取景窗口是偶数对齐的`
对五种 scale 都做了断言。

## 背景虚化

中间椭圆保持清晰，向外按 `feather` 过渡到模糊。

### 为什么是椭圆不是矩形

矩形边缘会在画面上留下明显的四道直边，观感像「贴了个窗户」。
椭圆配羽化更接近浅景深的自然过渡。

### 盒式模糊的可分离性

二维盒式模糊可以拆成水平 + 垂直两趟，复杂度从 O(r²) 降到 O(r)。
半径 8 时是 289 次采样降到 34 次 —— 每帧省下的正是 60fps 预算里最紧的那部分。

边缘用**夹取**而不是补零：补零会让画面边缘发黑，在视频会议里非常明显。

## 人像平滑

双边滤波的盒式近似：只对邻域内亮度差小于阈值的像素做平均。

真正的双边滤波按距离与亮度差双重加权（要算两次 exp），这里用「阈值内算 1、
阈值外算 0」替代 —— 少了乘加，但保留了**不糊边**这个关键性质。

两条断言直接对着这个性质写：

- `人像平滑降低噪点`：噪点图的方差必须下降；
- `人像平滑保住强边缘`：左半 50 / 右半 200 的硬边在平滑后两侧仍是 50 和 200。

## 与几何变换的配合

管线顺序是「效果 → 几何变换」：

```text
   解码帧 ──▶ 自动取景/虚化/平滑 ──▶ 旋转/裁切 ──▶ 共享内存
```

原因：虚化与平滑都不改尺寸，把它们放在几何变换前面，自动取景看到的是
**完整画面**而不是被旋转裁切过的局部。

自动取景算出的窗口会写进 `geometry.crop`，由几何变换真的去裁。
但如果窗口尺寸正好等于当前 DirectShow 协商的输出尺寸，就不必裁 ——
否则会出现「裁完尺寸变了，与协商模式不符」的问题（见 frame-transform.md）。

## 开关

控制消息新增四个字段，全部默认关闭：

```json
{ "autoFrame": true, "autoFrameScale": 0.75 }
{ "blur": 8 }
{ "smooth": 2 }
{ "autoFrame": false, "blur": 0, "smooth": 0 }
```

不默认开启是刻意的：这三个都是 CPU 逐像素运算，1080p 一帧 200 万像素，
不该因为「用户没说话」就悄悄跑起来吃掉 60fps 的预算。

关闭自动取景时会把 `focus_window` 与 `geometry.crop` 一起清掉 ——
只清一半会留下一个「窗口没了但裁切还在」的状态。

## 性能与边界

| 效果 | 1080p 单帧开销（量级） | 备注 |
| --- | --- | --- |
| 自动取景 | O(像素) 建显著性图 + O(格子²) 枚举 | downsample=8 时格子数约 3 万 |
| 背景虚化 | O(像素 × 半径 × 2) | 半径 8 → 每像素 34 次采样 |
| 人像平滑 | O(像素 × (2r+1)²) | 半径 2 → 每像素 25 次采样，最贵 |

三者的共同点：都是纯 CPU、无 SIMD。要优化的话顺序是：
先把盒式模糊换成滑动窗口（O(1)/像素），再考虑 SIMD。
但这三条路径默认都不走，所以优先级低于「先把功能接通」。

尺寸边界：画面小于 16×16 时自动取景直接返回无窗口；
小于 8×8 时虚化跳过；小于 4×4 时平滑跳过。测试覆盖了这三种边界。
