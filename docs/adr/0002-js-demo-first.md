# ADR 0002：阶段 0 用 JavaScript 验证链路，而不是直接上 Rust

- 状态：已采纳（临时决策）
- 日期：2026-11-24

## 背景

架构定案是"共享 Rust 核心 + 六端原生 UI"。但当前开发机**没有 Rust 工具链**，
而阶段 0 的目标是**尽快拿到真实的链路数字**，不是把最终架构搭起来。

## 决策

阶段 0 的 demo 用 Node.js（ESM）实现协议、抖动缓冲、时钟同步、设备发现、传输。
Rust 版本在阶段 1 重写，**但保持相同的模块边界与接口语义**。

## 理由

1. **阶段 0 的问题与语言无关**：协议是否正确、缓冲策略是否合理、时钟是否对齐，
   换语言不会改变答案。用 JS 能在几小时内跑通，用 Rust 要先把工具链装好。
2. **避免过早优化架构**：现在为"六端"设计抽象层，等第三个平台真的接入时会发现 40% 是错的。
3. **demo 即规范**：JS 实现可以作为 Rust 重写的**行为参照**，配合单元测试做逐条对齐，
   比两份文档互相对照可靠得多。

## 代价与边界

- 这份 JS 代码**不进入生产**，只作为参考实现 + 回归基线保留在 `legacy/` 或分支。
- 性能数字（本 demo 的 p50 ≈ 1.7ms）**只反映链路逻辑**，不代表最终产品的编解码性能。
- Rust 重写时必须让本 demo 的全部单元测试在新实现上通过。

## 何时撤销

阶段 1 开始，Rust 核心的第一个可运行版本通过全部既有测试后，本 ADR 标记为 Superseded。
